## 零之补、最关键的一处自伤：initramfs 里的 init 是不可执行的

前五轮"所有内核版本失败得一模一样"，真正原因是**我们自己的 initramfs 有问题**，与内核无关：

```
/usr/bin/busybox: a /bin/busybox sh script, Unicode text, UTF-8 text executable
/bin/busybox -> /usr/bin/busybox          (usrmerge 符号链接指回自己)
```

- WSL 里 `command -v busybox` 得到的是**一个脚本**，其 shebang 是 `#!/bin/busybox sh` → 解析后又指向自己 → 内核 exec `/init` 永远失败
- 即使它是真二进制，那也是 **x86_64** 的，在 ARM64 手机上同样无法执行
- 内核找不到可用 init ⇒ `No working init found` ⇒ 约 5 秒后 panic（`panic=10` 于是 46 秒回到 LineageOS）⇒ **日志永远写不出来**

**修复**：
1. 弃用 busybox，改用**交叉编译的静态 ARM64 C init**（`tools/natrium-init2.c`：mount/reboot/syslog 全用系统调用；三路输出：cache 分区 `/natrium-diag.txt`、`/dev/kmsg`、`/dev/ttyGS0` USB 串口）
2. 交叉工具链缺 ARM64 用户态头文件 → 安装 `libc6-dev-arm64-cross` 解决
3. 备用：从 Alpine 取真正的 aarch64 静态 busybox（`busybox-static` 包）→ 做出**带串口 shell 的标准 initramfs**（`tools/build-bb-initramfs.sh`）
4. **`verify_bootimg.py` 补上关键断言**：解包 ramdisk，检查 init 是否为 ELF、架构是否为 `ARM aarch64`、是否带可执行位
   （之前只检查"有没有 init"，正是这个漏洞让五轮测试白跑）

**注意**：因此"设备被上游归档 = 支持已损坏"这一结论**建立在前五轮无效测试之上**，现在**不成立**，需要重新评估。

### 已被证伪/修正的中间结论（记录以免重蹈）
1. ~~「内核跑到了用户态 init」~~ —— 那次"20 秒自重启"其实是 panic（`panic_timeout=10`）后自动重启，不是我们的 `sleep 20`。
2. ~~「`fastboot boot` 这条路不可用」~~ —— 可用；只是 ABL 交接慢，屏幕会先保留 fastboot 画面。
3. ~~「UFS PHY 缺失只是次要问题」~~ —— 它是 `=m`（模块），initramfs 无法加载 ⇒ **存储完全不可用**，导致日志无处可写。已修为内建。

## 四、如果这两版也不行 —— 剩下的手段（按性价比排序）

1. **接 UART 串口**（最直接）
   natrium 的调试串口在主板 **GPIO4/GPIO5**（设备树里标注 `MSM_UART_TX/RX`）。
   用一个 1.8V USB-TTL 转换器焊两根线，就能看到 **panic 原文**（哪一行、哪个驱动）。
   这是唯一能一步定位的办法；没有它，我们只能靠穷举配置。
   启动参数需加 `console=ttyMSM0,115200n8 earlycon`（我可以直接给你这样的镜像）。

2. **用 pmOS 官方预编译镜像做对照**
   下载 pmOS 给 xiaomi-natrium 的完整镜像，取其 boot.img 直接 `fastboot boot`。
   - 能启动 ⇒ 证明硬件/ABL 完全支持 mainline，问题在我们编出来的内核（那就继续查配置/补丁）
   - 也挂 ⇒ 说明你这台机器/固件有特殊性（比如 bootloader 版本）
   （本次会话中我没能定位到 pmOS 镜像的下载地址，需要继续找）

3. **去 msm8996-mainline 社区问**
   维护者是 Yassine Oudjana（Tooniis），项目：<https://gitlab.com/msm8996-mainline/linux>
   问法建议："natrium (Mi 5s Plus) with v6.18.7-msm8996 + config-postmarketos-qcom-msm8996.aarch64 panics before init when booted via fastboot boot / flashed boot. Any known natrium-specific gotcha (board-id / pmic-id / ABL DTB selection)?"
   —— 他们手上真有设备，能直接对比。

4. **换一种启动方式排除 ABL 因素**：`fastboot flash boot` 我们的镜像（boot 分区被我们占用，行为更接近正常启动路径；失败则回滚）。
